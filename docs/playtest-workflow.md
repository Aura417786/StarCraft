# 独立试玩与问题交接

正式开发使用 Git 仓库。测试使用从特定提交导出的独立运行副本。Windows 本地工作台通过 `Game/` 打开正式仓库，测试资料归入同级的 `AI_Development/`。项目成员可以按自己的磁盘路径建立工作台。

| 位置 | 保存内容 |
| --- | --- |
| `AI_Development/Builds/` | 每轮版本的 ZIP、运行目录、完整提交和 SHA-256 |
| `AI_Development/Reports/` | DeepSeek 或人工测试报告，关联准确版本 |
| `AI_Development/Backlog/` | 去重后的问题、优先级、负责人和复测状态 |
| `AI_Development/Screenshots/` 与 `Videos/` | 带版本与复现条件的测试证据 |
| `AI_Development/Metrics/` | 窗口尺寸、画质、浏览器、硬件和性能采样 |
| `AI_Development/History/` | 检查点、阶段标签、改动范围和每轮结果 |

1. **改前留检查点。** 检查 `git status --short`。在本轮变更前，从已确认的起点建立本地 `checkpoint/…` 标签，记录完整提交。发现已有未提交工作时，先保留并记录，再在独立 worktree 中开展新任务。标签对应已提交的内容。
2. **验收后冻结版本。** 为完成的阶段创建新版本标签。导出该标签对应的 HTML、脚本、样式、运行素材和许可证，生成新的测试目录和 ZIP。记录完整提交及 ZIP 的 SHA-256。第一轮 `v18-750af60` 对应 `v18` 游戏发布提交。
3. **按版本交接。** 给测试方提供本轮测试包、测试提示词和实际证据。DeepSeek 的输出归入 `Reports/`，附环境、复现步骤、预期结果、实际结果、严重程度与证据。实际游玩和根据材料推断的内容分开写。
4. **修复并复测。** Codex 根据报告复现问题，从正式仓库修复。输出新的冻结测试版本，用同样的环境和步骤复测。历史测试包及其标签保留，便于回查差异。

测试包可双击 `Game/index.html` 运行兼容模式。要测实时三维和水面着色，用本地 HTTP 服务指向该版本的 `Game/`，并在浏览器选择相应画质。报告、录像和临时性能数据留在本机工作台，正式 Git 仓库保留维护说明和可复现的开发脚本。
