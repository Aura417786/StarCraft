# v35.1 黑洞视觉修复

基线：`111c4d1710a0704e952c662ebd85b858a7315655`（v35）。
本次只修复黑洞及其空间裂缝的呈现，不调整敌人血量、伤害、技能时序或玩家成长。

## 原因与修改

用户截图是维度噬口的 `riftFold`，它由 `drawAlienHazard` 直接分发到
`drawAlienMechanic`。原先这里仍绘制透明紫圆盘、五条细弧和一条虚线，
没有经过已更新的普通漩涡绘制入口。

- 将真实 `riftFold` 路径接入共享黑洞表面；普通虚空漩涡、引力井和奇点蓄力也使用它。
- 新增原创 RGBA 吸积盘素材：黑色核心、蓝色光缘、不对称紫色流光、细密尘埃与柔化外围。
- 一个共享、限定分辨率的 WebGL2 表面让内外层纹理以不同速度流动；每帧最多重绘两次。
  高画质 512×512，中画质 320×320，动画时钟量化到 30 Hz。
- 低画质、WebGL 不可用或上下文丢失时使用同一素材的 Canvas 旋转版本。
  减少动态模式冻结旋转；文件直接打开也走 Canvas 兼容路径。
- 裂缝预警仍沿真实斩击线显示；激活后改为透明能量层、暗芯与流动光缘，避免实色矩形挡住黑洞。
- 薄环形冲击波继续使用原本覆盖完整危险宽度的材质，保持内外边界及安全中心。
  不能用吸积盘透明外沿替换危险细环。

没有修改引力、子弹偏折、裂缝命中、护盾、血量或存档代码。

## 有限场景性能数据

1440×900，Chrome，单个黑洞＋Boss模型＋背景，固定战斗状态；
每档连续取样4.5秒，期间无录像。数据来自 `release-blackhole/report.json`。
这是渲染夹具，不是完整自然战役，也不是跨硬件帧率承诺。

| 画质 | CPU绘制p95 | RAF间隔p95 | 最大RAF间隔 |
| --- | ---: | ---: | ---: |
| 低 | 2.0 ms | 7.0 ms | 15.2 ms |
| 中 | 2.8 ms | 13.0 ms | 26.4 ms |
| 高 | 3.1 ms | 13.6 ms | 43.2 ms |

JS堆快照约121–123 MB，不能当作总进程内存或GPU显存。
新增素材1,399,515字节（约1.40 MB）；最多新增一个WebGL上下文。
从高画质切回低画质后会保留已创建的共享上下文，但不继续绘制它。

## 工具与限制

使用 ask-matt 路由、implement、creating-game-combat-vfx 的运行时整合原则、
threejs-aaa-graphics-builder 的材质/预算参考，并完成两轴代码审查。
图像由内置图像生成工具原创制作；PowerShell、Node、Playwright、Chrome负责整合和验证。
不增加引擎依赖，不使用外部CDN，不复制参考截图作为游戏素材。

这仍是适配现有2D战场的材质与流动着色器，不是完整相对论光线追踪。
低画质保留形态和细节，但没有内外层差速流动。没有在本轮重做全战役平衡，
也未重新自然通关或测试实体手柄；本轮没有涉及这些逻辑。

## 重现与交付

运行 `tools/testkit/blackhole-review.cjs <Game目录> <新证据目录>` 验证本次修复。
加入 `frames` 可仅重拍9张画面；`baseline` 用于旧版对照。
Node需要可用的Playwright依赖，可通过 `NODE_PATH` 指定已有测试依赖目录；
`CHROME_PATH` 指向Chrome可执行文件。

独立冻结版本为 **v35.1**，标签 **v35.1-blackhole**。
Builds中另存ZIP、SHA-256、逐文件manifest及START.txt，保留v35不覆盖。
从游戏目录启动HTTP服务器，再用浏览器打开相同网址以沿用该网址的存档。
公开站点可能仍运行旧部署；源码推送并不等于所有托管站点已更新。
